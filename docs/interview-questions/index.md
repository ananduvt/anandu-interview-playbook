## 📚 How Questions Are Formatted

Each question includes:

1. **Collapsible Minimal Answer** (3-4 lines max)
   - Click to expand and see the quick answer
   - Covers the core concept concisely
   
2. **Link to Detailed Topic**
   - Points to comprehensive documentation
   - Use for deeper understanding and examples
   - Perfect for pre-interview study

**Format:**
```html
<details>
<summary>Question Text Here?</summary>

**Answer:** Minimal explanation (3-4 lines)

📚 [Learn more: Topic Name](link-to-detailed-topic)
</details>
```

**Example:**
```html
<details>
<summary>What is a HashMap?</summary>

A HashMap uses hash codes to map keys to values with O(1) average access time. It handles collisions via chaining (linked lists) or red-black trees (Java 8+). Not thread-safe; use ConcurrentHashMap for concurrent access.

📚 [Learn more: Java Collections](../../java-collections-concurrency/collections.md)
</details>
```

## Interview Tips

### **Coding Questions**
- **Think aloud**: Explain your approach before coding
- **Clarify**: Ask about constraints, edge cases, examples
- **Brute force first**: Start simple, then optimize
- **Test**: Walk through examples, check edge cases
- **Complexity**: State time/space complexity before submitting

### **Verbal Questions**
- **Understand the question**: Rephrase to confirm understanding
- **Structured answer**: 
  1. Direct answer
  2. Why (reasoning/trade-offs)
  3. Examples (real-world or code)
  4. Alternatives (when applicable)
- **Deep dive**: Be ready for follow-ups; show depth
- **Connect concepts**: Link to related topics when relevant

### **General Tips**
- **Be honest**: "I don't know, but I'd approach it this way..."
- **Ask clarifications**: Better to understand than assume
- **Discuss trade-offs**: Compare approaches (speed vs readability, etc.)
- **Show enthusiasm**: Problem-solving mindset, curiosity
